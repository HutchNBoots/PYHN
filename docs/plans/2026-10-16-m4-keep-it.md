# M4: Keep it (export, autosave, polish, soak)

Spec: `docs/feature-spec.md` F7 (export and autosave) and F0.1, F0.3, F0.4. This is the last v1
milestone.

Milestone build: work survives closing the app, a crash or a call, losing at most the last 5 s
(F7.4). Relaunch restores the session, with the state first and the tape audio in the background
(F7.6). Export WAV on the Tape screen is two taps to the share sheet (F7.1). The known M1–M3
gaps are closed.

## Engine module (engine/; contract: the M4 section of `NativeEngine.kt`)

- **Tape persistence (F7.5):**
  - The audio thread records which frames it changes (takes, commits, clears, undo/redo swaps)
    into a lock-free SPSC ring.
  - A writer thread copies those regions to per-track files plus a metadata file (version,
    rate, length, frames-per-bar, track flags), so the files always describe a consistent tape.
  - The writer reads tape memory for those regions without racing the audio thread. One way:
    the audio thread copies changed blocks into the ring itself, which is bounded and drops
    nothing, and falls back to "rewrite this track" if the ring would overflow.
  - `flushTape` waits for the writer to drain.
- **Load (F7.6):** a loader thread reads and validates the files into a staging buffer. The
  audio thread then swaps them in incrementally, as undo does, and `TapeState.loading` covers
  it. A missing, corrupt or wrong-rate file loads nothing, never crashes, and keeps the old
  files until a new take overwrites them.
- **Export (F7.2, F7.3):**
  - The audio thread copies a snapshot of the tape incrementally into an export buffer.
  - A background thread renders it offline through the same `ChannelStrip`, master volume and
    `MasterBus` code (with the mixer values captured at the start) and writes a 24-bit WAV,
    faster than real time.
  - An offline render and a live capture of the same tape and settings must be bit-identical.
- **Drum kit off the startup path:** the kit renders on a background thread at construction.
  The synths sound first, and the drum slot is silent until the kit is ready (F2 decision,
  F0.1).
- JNI for the new calls; the `TapeState` layout gains `loading`.

## UI and storage module (app/)

- **Session store (F7.4, F7.7):** a pure-Kotlin, versioned save format for everything the UI
  mirrors: per-slot synth values, presets, locks and section; drum params; all patterns; mix
  and channel params; tempo; selected slot and screen.
  - Writes are atomic (a temp file plus a rename) and keep the previous good file. A corrupt
    file falls back to it, never to a crash or a dialog.
  - Older versions upgrade on load.
- **Autosave:** at most 5 s after any change, and at once on `onStop` (with `flushTape`).
  - On launch the state loads before the first sound; first launch keeps the demo content.
  - The UI then pushes the restored state to the engine and calls `loadSavedTape`.
- **Export flow:** Export WAV renders to the app's cache directory, shows progress on the Tape
  screen, then opens the Android share sheet through a FileProvider: two taps in total.
- **Polish:**
  - a clear-pattern control on the Seq screen
  - beat divisions shown when the LFO is tempo-synced (using the engine's rule)
  - the app id becomes `com.groovebox` and the name "Groovebox" (versionName 0.4.0). Doing it
    now, before any save data exists, costs nothing: the owner uninstalls the spike app once.
